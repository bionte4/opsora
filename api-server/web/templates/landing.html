Platform CI mandiri

Build selesai. Tim langsung tahu.

Opsora menerima push dari GitHub, menjalankan setiap langkah di container terpisah, lalu mengirim hasilnya ke Telegram. Kalau gagal, penyebabnya dikutip dari log. Kalau rilis rusak, satu perintah mengembalikan versi sebelumnya.

Setiap bagian dipakai setelah yang sebelumnya menghasilkan data sungguhan. Tidak ada kotak yang hanya tampil di diagram.

Pipeline di container

File .opsora.yml menentukan image dan langkah. Satu container per langkah, tanpa soket Docker dan tanpa rahasia platform.

Status di GitHub

Commit mendapat status pending, lalu hijau atau merah. Log tiap langkah bisa diikuti dari konsol.

Telegram

Satu pesan per build: repositori, commit, langkah yang gagal, dan kutipan log. Chat lain tidak bisa memberi perintah.

Analisis kegagalan

Model menjelaskan langkah yang gagal dan menunjuk baris log. Nomor baris dicek, jadi kutipan tidak dikarang.

ChatOps

/status, /logs, /rerun, dan /rollback lewat bot yang sama. Perintah masuk ke API, bukan ke Redis.

Deploy dan rollback

Image ditandai dengan commit. Kalau container baru mati, rilis sebelumnya tetap aktif dan bisa dinyalakan lagi.
